# Visual Moves

Visual moves are the palette. Use them to encode meaning, not to decorate text. Pick several candidate moves for each slide, then choose the one that best fits the audience, density, and deck-level design language.

## Move Families

### Radial Ecosystem

Best for: stakeholder systems, platform ecosystems, 360-degree partnerships, value networks, capability centers.

Encodes: center/periphery, orbit, mutual reinforcement, shared ownership, ecosystem coverage.

Variation levers: number of rings, number of nodes, open versus closed circle, center emphasis, annotation density, one accent family.

Compatible lenses: `solution-oriented`, `high-energy-html`. Use sparingly in `minimalist-executive`; avoid repeating hub-spoke forms across adjacent slides.

### Layer Stack

Best for: platforms, maturity models, capability hierarchy, architecture layers, operating model foundations.

Encodes: dependency, foundation, abstraction, priority, progression from base to outcome.

Variation levers: pyramid, stepped layers, horizontal platform stack, offset blocks, highlighted layer, side annotations.

Compatible lenses: `solution-oriented`, `tactical-operational`, `minimalist-executive` when simplified.

### Progression Path

Best for: roadmaps, transformation journeys, maturity growth, implementation stages, customer journeys.

Encodes: time, sequence, movement, decisions, handoffs, stage gates.

Variation levers: straight line, curved path, milestone cards, lanes, chapter breaks, emphasized current state.

Compatible lenses: `solution-oriented`, `high-energy-html`, `minimalist-executive`. In `tactical-operational`, add owners, gates, or risk/status markers.

### Operating Rhythm

Best for: delivery methods, governance, team ceremonies, workplans, agile/process views.

Encodes: cadence, handoffs, parallel work, accountability, repeated loops.

Variation levers: swimlanes, loop, calendar band, phase columns, role rows, activity/outcome split.

Compatible lenses: `tactical-operational`, `solution-oriented`. Keep it scannable; do not create method walls.

### Decision Compare

Best for: current/future, options, tradeoffs, pros/cons, criteria, recommendation rationale.

Encodes: contrast, tension, difference, relative fit, decision path.

Variation levers: mirrored panels, matrix, spectrum, before/after path, highlighted recommendation, risk/value axis.

Compatible lenses: all. `minimalist-executive` should reduce to the decisive contrast; `tactical-operational` should expose criteria and signals.

### Modular Blocks

Best for: capabilities, solution components, offers, delivery building blocks, "how we fit together" stories.

Encodes: composability, connection, assembly, reusable capabilities, sequencing.

Variation levers: block count, stacked versus scattered, 2D versus pseudo-3D, color family, label density, selected block emphasis.

Compatible lenses: `solution-oriented`, `high-energy-html`. Avoid equal-weight feature-card grids unless equal weight is the point.

### Evidence Board

Best for: research synthesis, findings, current-state observations, voice-of-customer, workshop outputs.

Encodes: grouped evidence, triangulation, signal versus noise, themes.

Variation levers: cards, tags, annotated clusters, proof strips, source markers, one highlighted implication.

Compatible lenses: `minimalist-executive`, `tactical-operational`, `solution-oriented`. Use a highlighted implication so evidence does not become decoration.

### Editorial Reset

Best for: covers, section dividers, big claims, quotes, transitions, emotional pacing.

Encodes: pause, emphasis, chapter shift, confidence, humanity.

Variation levers: blue field, white field, full-bleed approved image, large type, color bar, single organic line accent.

Compatible lenses: `minimalist-executive`, `high-energy-html`. In all lenses, keep covers and resets subordinate to Slalom template behavior.

### Icon Matrix

Best for: option sets, capability lists, services, principles, technology categories.

Encodes: parallel categories, coverage, menu, taxonomy.

Variation levers: grid density, icon size, label hierarchy, selected cells, grouping rows, category headers.

Compatible lenses: `tactical-operational`, `solution-oriented`. Use icons only when they improve scanning or meaning.

## Selection Rules

- Use the slide's job to select candidate moves; do not select a move because a starter slide exists.
- When the package support set has a matching primitive, use its component class as the first draft and adapt it through count, scale, orientation, density, emphasis, and annotations.
- Write custom CSS when the slide needs a genuinely different structure, but do not reimplement the same primitive under a deck-specific class name by default.
- Prefer moves that make the relationship visible without reading every word.
- Vary geometry across adjacent slides: radial after radial gets stale unless the story is intentionally reinforcing a system.
- If the content is too dense for the chosen move, split the slide or move detail into appendix-style support.
- If the visual move does not change understanding, simplify it.

## Sameyness Checks

Before rendering, scan the deck:

- Are three or more adjacent slides using the same grid?
- Does every slide have equal-sized panels?
- Are icon cards doing work, or just replacing bullets?
- Are all comparisons two columns?
- Are roadmaps all flat left-to-right bands?
- Are visuals showing relationships, or just surrounding text?
