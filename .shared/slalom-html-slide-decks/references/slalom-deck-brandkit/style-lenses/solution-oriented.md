# Style Lens: Solution-Oriented

Use this lens when the deck needs to make the solution concrete: how it works, what connects, where decisions happen, and why it is credible.

Best for:

- solution POVs
- architecture and operating model sections
- sales pursuit solution pages
- transformation roadmap decks
- AI-enabled delivery model explanations

## Design Read

This lens reads as a practical Slalom solution narrative: structured, clear, system-aware, and credible enough for delivery executives.

## Visual Rules

- Show relationships, not only categories.
- Make boundaries and handoffs visible.
- Use Slalom Blue for the primary spine, core, or selected path.
- Use accent colors to distinguish roles, stages, risks, or outcomes.
- Prefer labels that explain the action: "qualify risk", "synthesize evidence", "approve route", "preserve playbook".
- Include ownership and decision points when the solution affects delivery governance.

## Layout Moves

- lifecycle rail with decision gates
- layer stack or platform stack
- capability map with highlighted path
- operating model loop
- role / leverage / signal matrix
- risk-value tradeoff
- proof strip tied to the model

## Content Rules

- Use verbs over nouns.
- Name the mechanism that creates value.
- Keep "AI" in a support role unless the brief explicitly requires an AI product story.
- Show how the pilot or model becomes repeatable.
- Avoid unsupported quantified claims.

## Avoid

- architecture boxes that only list systems
- hub-spoke diagrams repeated across multiple slides
- fake product UI or fake dashboards unless the slide is specifically about an interface
- purely conceptual frameworks with no owner, signal, or path
- roadmaps where every phase has equal weight

## QA

Before finalizing, ask:

- What system relationship is now clearer?
- Where is the decision path?
- Who owns the loop or handoff?
- What proof or signal makes the solution credible?
