## Repo-Wide Observations

- **Root aggregator:** [pom.xml](pom.xml) is a `packaging=pom` Maven aggregator listing all seven services as modules; Spring Boot `2.6.3` and Java 17 pinned in the parent.
- **Orchestration script:** [docker-run.sh](docker-run.sh) computes the host IP via `hostname -I` and passes it into each container as the `ipaddr` env var; this is what carries Eureka's addressable hostname into the running services.
- **CI:** [.github/workflows/ci.yml](.github/workflows/ci.yml) runs `./mvnw -B -ntp -DskipTests=false test` for the Java modules and `npm ci` + `npm test -- --coverage --watchAll=false --ci` for the React UI; JaCoCo + Surefire artifacts are uploaded.
- **Shared data-tier assets:** [resources/schema.cql](resources/schema.cql), [resources/schema.sql](resources/schema.sql), [resources/dataload.sh](resources/dataload.sh), and [resources/parse_metadata_json.py](resources/parse_metadata_json.py) live outside any service's tree; treating them as versioned migrations owned by the consuming services (Suggestions cart-3, checkout-2, login-5, products-2) is a repeated theme in this report.
- **Consistency gap:** `login-microservice` is the only service missing a `Dockerfile` and Spring Actuator — bringing it in line with its siblings is the single highest-leverage repo-wide fix.
- **AI factors:** No service in this repo currently uses LLMs, agents, prompts, or vector stores. Factors XIII–XVI (Prompts as Code, State as a Service, Observability for Non-determinism, Trust & Safety by Design) do not apply and are omitted from every section above.
